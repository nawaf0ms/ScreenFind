# ScreenFind

> © 2026 **[nawaf0ms](https://github.com/nawaf0ms)** — رخصة MIT (انظر [LICENSE](LICENSE)).

بحث نصي داخل أي شيء معروض على الشاشة — حتى لو كان المحتوى لا يدعم البحث أصلاً (PDF ممسوح
ضوئياً، كتاب مصوّر، عارض محمي، جلسة Remote Desktop، تطبيق قديم بلا `Ctrl+F`).

اضغط **Ctrl+Shift+F** → يظهر صندوق بحث عائم → يقرأ التطبيق النافذة التي كنت تنظر إليها
(عبر UI Automation أولاً، ثم OCR) → يظلّل النتائج فوق الشاشة مباشرة.

**العربية والإنجليزية بنفس درجة الأهمية**، والتطبيق يعمل **أوفلاين بالكامل** — صفر اتصال بالشبكة.

## المتطلبات

| | |
|---|---|
| نظام التشغيل | Windows 10 build 19041 أو أحدث |
| للبناء | .NET 8 SDK — التشغيل النهائي self-contained بلا متطلبات |
| لغات OCR | العربية والإنجليزية مثبّتتان في ويندوز |

للتحقق من لغات OCR المثبّتة:

```bash
dotnet run --project ScreenFind.Feasibility -- langs
```

إن كانت العربية غير مثبّتة:
`Settings → Time & Language → Language & region → العربية → Options → Basic typing / OCR`

## التثبيت

**نسخة جاهزة:** نزّل `ScreenFind-1.0.0.msi` من
[صفحة الإصدارات](https://github.com/nawaf0ms/ScreenFind/releases/latest) وشغّله — بلا صلاحيات
مدير وبلا حاجة إلى تثبيت .NET.

### البناء من المصدر

```bash
powershell -ExecutionPolicy Bypass -File build\build-installer.ps1
```

ينتج `dist\ScreenFind-1.0.0.msi` — مُثبِّت **لكل مستخدم** (بلا صلاحيات مدير) يضع البرنامج في
`%LOCALAPPDATA%\Programs\ScreenFind` مع اختصار في قائمة ابدأ، ويشغّله بعد التثبيت مباشرة.
يسأل المُثبِّت في شاشته الثانية عن **لغة الواجهة** (العربية / English)، ويُخزّن الاختيار في
`HKCU\Software\ScreenFind\Language` ليُستخدم عند أول تشغيل فقط — بعدها ملف الإعدادات هو المرجع.

```bash
msiexec /i dist\ScreenFind-1.0.0.msi
```

للتثبيت الصامت بلغة محددة: `msiexec /i ScreenFind-1.0.0.msi UILANG=en /qb`
لإلغاء التثبيت: `msiexec /x dist\ScreenFind-1.0.0.msi` أو من «التطبيقات المثبّتة».

بناء المُثبِّت يتطلب: `dotnet tool install --global wix --version 5.0.2`
(النسخة 5 مجانية؛ النسخ 6+ تشترط قبول اتفاقية OSMF.)

## البناء والتشغيل من المصدر

```bash
dotnet build ScreenFind.sln
```

```bash
dotnet run --project ScreenFind.App
```

> **التطبيق بلا نافذة رئيسية.** بعد التشغيل يظهر إشعار «جاهز» وأيقونة العدسة في شريط النظام
> (قد يخفيها ويندوز 11 داخل السهم المطوي — ثبّتها بسحبها إلى الشريط). في أول تشغيل تُفتح شاشة
> الإعدادات تلقائياً. تشغيل نسخة ثانية لا يفتح شيئاً: النسخة العاملة تُظهر صندوق البحث ثم تُغلق
> الثانية نفسها.

### الاختصارات

| المفتاح | الوظيفة |
|---|---|
| `Ctrl+Shift+F` | إظهار/إخفاء صندوق البحث |
| `Enter` / `F3` | النتيجة التالية |
| `Shift+Enter` | النتيجة السابقة |
| `Ctrl+C` | نسخ كل النص المستخرَج إلى الحافظة |
| `Esc` | إغلاق كل شيء وإعادة التركيز للنافذة الأصلية |

قائمة أيقونة شريط النظام: **بحث في الشاشة** · **الإعدادات…** · **إنهاء**.

### حزمة تنفيذية واحدة (بلا مُثبِّت)

```bash
dotnet publish ScreenFind.App -c Release
```

ملف واحد self-contained في
`ScreenFind.App\bin\Release\net8.0-windows10.0.19041.0\win-x64\publish`.

## الإعدادات

من أيقونة شريط النظام ← «الإعدادات…». تُحفظ في `%APPDATA%\ScreenFind\settings.json`
وتُطبَّق فوراً بلا إعادة تشغيل:

| المجموعة | ما يمكن تغييره |
|---|---|
| اللغة | عربي / English / حسب لغة ويندوز — تُطبَّق على كل الواجهة واتجاهها فوراً |
| الاختصار العام | أي تركيبة بمُعدِّل واحد على الأقل — يُعاد تسجيلها فور الحفظ |
| الاستخراج | تفعيل طبقة UI Automation، لغات الـ OCR (من المثبّت فعلياً)، معامل التكبير، طريقة إعادة التحجيم، التدرّج الرمادي |
| المطابقة | المطابقة الضبابية، أدنى تشابه (0.60–1.00)، أقصى عدد نتائج |
| ألوان التظليل | لون كل النتائج، النتيجة النشطة، إطارها — بصيغة `#AARRGGBB` |
| السلوك | مهلة البحث أثناء الكتابة، التشغيل مع بدء ويندوز (مفتاح `HKCU\...\Run` فقط) |

تغيير إعدادات الاستخراج يُبطل النص المخزَّن ويعيد بناء المسار من جديد.

## بنية الحل

```
ScreenFind.Core/          لا يعتمد على WPF — كل المنطق قابل للاختبار
├── Capture/              ICaptureService, GraphicsCaptureService, BitmapPixels, ContentHash
├── Extraction/           ITextExtractor, UiaTextExtractor, OcrTextExtractor,
│                         IOcrEngine, WindowsOcrEngine, ImagePreprocessor,
│                         CoordinateMapper, ReadingOrder, ExtractionPipeline
├── Text/                 TextNormalizer, IndexMap, MatchEngine, Levenshtein
├── Input/                HotkeyListener
├── Configuration/        ScreenFindSettings
├── Models/               Rect, WordBox, ExtractedDocument, Match
└── Interop/              Win32.cs — كل الـ P/Invoke في مكان واحد

ScreenFind.App/           WPF: SearchBarWindow, OverlayWindow, SettingsWindow,
                          AppOrchestrator, TrayIcon, SingleInstance, StartupRegistration
ScreenFind.Cli/           كونسول يطبع الكلمات المستخرَجة وإحداثياتها
ScreenFind.Feasibility/   قياس دقة OCR + توليد عينات اختبار
ScreenFind.Tests/         77 اختباراً: المطبّع، IndexMap، محرك المطابقة، الإحداثيات، التكامل
build/                    app.manifest (PerMonitorV2)، الأيقونة، ScreenFind.wxs، build-installer.ps1
```

### مسار المعالجة

```
Ctrl+Shift+F
  └─ حفظ GetForegroundWindow()      ← قبل ظهور أي واجهة
     └─ ExtractionPipeline
          ├─ Tier 1: UiaTextExtractor      نص دقيق + إحداثيات، بلا التقاط
          └─ Tier 2: OcrTextExtractor      التقاط → معالجة مسبقة → ar + en بالتوازي → دمج
             └─ TextNormalizer + IndexMap → MatchEngine (حرفي ثم ضبابي)
                └─ OverlayWindow لكل شاشة
```

## أدوات التشخيص

```bash
dotnet run --project ScreenFind.Cli -- --once 4 --search "المكتبة"
```

يطبع النافذة المستهدفة، مصدر الاستخراج، الزمن، الكلمات بإحداثياتها الفعلية، ونتائج البحث.
`--ocr-only` و `--uia-only` لعزل الطبقتين.

```bash
dotnet run --project ScreenFind.Feasibility -- gate
```

يولّد عينات اصطناعية (نص مرسوم، شبيه بمسح ضوئي، متدهور بشدة) بالعربية والإنجليزية، يقيس دقة
الـ OCR على كل حالة ولكل طريقة معالجة مسبقة، ويكتب تقريراً في `docs/`. **شغّله على جهازك**:
النتيجة تعتمد على حزم اللغة المثبّتة لديك. لقياس محتوى حقيقي، ضع لقطات الشاشة في
`samples/synthetic/` باسم `ar_*_scan.png` مع ملف `.txt` يحوي النص الصحيح.

```bash
dotnet run --project ScreenFind.Feasibility -- dump <image.png> ar x2-bicubic
```

يطبع مخرجات المحرك الخام لصورة واحدة (نصوص + صناديق) — أسرع طريقة لتشخيص خطأ في التعرّف.

## قرارات تقنية

1. **ترتيب الكلمات في السطر العربي.** محرك ويندوز يعيد كلمات السطر بترتيب **بصري**
   (يسار→يمين)، أي معكوساً منطقياً. بدون تصحيحه ينهار البحث عن العبارات والنص المنسوخ
   رغم أن الكلمات نفسها صحيحة. `ReadingOrder` يعيد ترتيب كل سطر حسب اتجاهه.
2. **الدمج بين المحرّكين على مستوى السطر لا الكلمة.** دمج الكلمات فردياً يخلط ترتيب القراءة
   في العربية. يُختار لكل منطقة السطرُ الأعلى وزناً = (عدد حروف السكربت المطابق × نسبة
   المطابقة)؛ النسبة وحدها لا تكفي لأن مخرجات المحرك الإنجليزي على سطر عربي تكون حروفاً
   لاتينية عشوائية بنسبة مطابقة 100%.
3. **`IOcrEngine` نقطة استبدال واحدة.** محرك ويندوز ممتاز على النص المرسوم وأضعف على المحتوى
   شديد التدهور؛ استبداله بـ PaddleOCR أو Tesseract يكلّف إضافة كلاس واحد لا أكثر، ولا تتسرّب
   أنواع `Windows.Media.Ocr` خارج `WindowsOcrEngine`.
4. **`Rect` خاص بالنواة** بدل `System.Windows.Rect` حتى تبقى `ScreenFind.Core` بلا WPF.
5. **صندوق البحث يأخذ التركيز.** الكتابة تتطلب تركيز لوحة المفاتيح؛ الشرط الجوهري (حفظ
   النافذة الهدف **قبل** إظهار الواجهة) محفوظ.
6. **`ValuePattern` غير مستخدم في طبقة UIA** لأنه لا يوفّر إحداثيات لكل كلمة، والتظليل بلا
   إحداثيات لا معنى له. تلك الحالات تسقط إلى OCR.
7. **معالجة الصور رمادية قبل التكبير** (نفس النتيجة برُبع العمل)، وبيكيوبيك Catmull-Rom منفصل
   المحورين. التكبير يُقلَّص تلقائياً إن تجاوزت الصورة 24 مليون بكسل أو 10000 بكسل في أي بُعد.
8. **الترجمة بقاموس C# لا بملفات resx.** كل النصوص في ملف واحد
   ([Loc.cs](ScreenFind.App/Localization/Loc.cs)) بدل satellite assemblies — أوضح للمراجعة،
   وبلا مفاجآت في حزمة single-file. النوافذ تُعاد بناؤها عند تغيير اللغة لأن الاتجاه
   (RTL/LTR) يُحسم وقت الإنشاء.
9. **مقاس النوافذ يُضبط بالبكسل الفعلي.** تهيئة WinForms (أيقونة الـ tray) قد تُغيّر سياق DPI
   للخيط، فيبني WPF إطاراً بمقاس 96 DPI بينما يرسم محتواه مكبّراً فيُقصّ. الحل: تثبيت الخيط
   على PerMonitorV2 + ضبط المقاس والتوسيط بـ `SetWindowPos` بعد أول رسم، مع قصّه على مساحة
   العمل حتى لا تتجاوز النافذة حدود الشاشة.
10. **نسخة واحدة فقط.** النسخة الثانية كانت تفشل صامتة في تسجيل الاختصار وتبدو كأن التطبيق لا
    يعمل؛ صارت تُشير للنسخة العاملة لتُظهر صندوق البحث ثم تُغلق نفسها.
11. **نصوص المُثبِّت بالإنجليزية.** جدول نصوص MSI مرتبط بصفحة ترميز واحدة؛ إبقاؤه على 1252
    يضمن عمله على كل الأنظمة. واجهة التطبيق نفسها تدعم العربية والإنجليزية.

### مطبّات ويندوز المُعالَجة

| المطبّ | الحل |
|---|---|
| التطبيق يلتقط واجهته نفسه | `SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE)` |
| ضياع النافذة المستهدفة | حفظ `GetForegroundWindow()` **قبل** إظهار الواجهة |
| انحراف التظليل على شاشات مكبّرة | `PerMonitorV2` + تحويل الإحداثيات في `CoordinateMapper` وحده |
| بطء الـ OCR | كل شيء `async` + cache بهاش اللقطة |
| تعدد الشاشات | طبقة تظليل لكل شاشة بمعامل DPI الخاص بها |
| استثناءات UIA العشوائية | `try/catch` حول كل استدعاء + مهلة ثانيتين |
