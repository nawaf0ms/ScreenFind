# ScreenFind

> © 2026 [nawaf0ms](https://github.com/nawaf0ms) — رخصة MIT (انظر [LICENSE](LICENSE)).

أداة ويندوز للبحث عن نص داخل ما هو معروض على الشاشة، حتى لو كان المحتوى نفسه لا يدعم البحث:
ملف PDF ممسوح ضوئياً، كتاب مصوّر، عارض يمنع التحديد والنسخ، جلسة سطح مكتب بعيد، أو تطبيق قديم
بلا `Ctrl+F`.

اضغط `Ctrl+Shift+F` فيظهر صندوق بحث صغير أعلى الشاشة. يقرأ التطبيق النافذة التي كنت تنظر إليها،
أولاً عبر UI Automation، وإن لم ينجح يلتقط صورة النافذة ويشغّل OCR عليها، ثم يرسم مستطيلات
تظليل فوق النتائج في أماكنها على الشاشة.

العربية والإنجليزية مدعومتان بنفس القدر. لا يوجد أي اتصال بالشبكة في التطبيق، كل شيء يجري محلياً.

## المتطلبات

| | |
|---|---|
| نظام التشغيل | Windows 10 إصدار 19041 أو أحدث |
| للبناء من المصدر | ‏.NET 8 SDK (الحزمة النهائية مستقلة ولا تحتاج .NET على جهاز المستخدم) |
| لغات OCR | حزمتا العربية والإنجليزية مثبّتتان في ويندوز |

لمعرفة لغات OCR الموجودة على جهازك:

```bash
dotnet run --project ScreenFind.Feasibility -- langs
```

إن لم تكن العربية مثبّتة، أضفها من:
`Settings → Time & Language → Language & region → العربية → Options → Basic typing / OCR`

## التثبيت

نزّل `ScreenFind-1.0.0.msi` من [صفحة الإصدارات](https://github.com/nawaf0ms/ScreenFind/releases/latest)
وشغّله. المُثبِّت لكل مستخدم على حدة، لا يطلب صلاحيات مسؤول، ويضع البرنامج في
`%LOCALAPPDATA%\Programs\ScreenFind` مع اختصار في قائمة ابدأ. يسألك أثناء التثبيت عن لغة الواجهة
(العربية أو الإنجليزية)، ويحفظ الاختيار في `HKCU\Software\ScreenFind\Language` لأول تشغيل فقط،
وبعدها يصبح ملف الإعدادات هو المرجع.

للتثبيت الصامت بلغة محددة:

```bash
msiexec /i ScreenFind-1.0.0.msi UILANG=en /qb
```

لإلغاء التثبيت: `msiexec /x ScreenFind-1.0.0.msi` أو من «التطبيقات المثبّتة» في ويندوز.

### بناء المُثبِّت بنفسك

```bash
powershell -ExecutionPolicy Bypass -File build\build-installer.ps1
```

يحتاج أداة WiX: `dotnet tool install --global wix --version 5.0.2`
(النسخة 5 مجانية، والنسخ الأحدث تشترط قبول اتفاقية OSMF.)

## التشغيل من المصدر

```bash
dotnet build ScreenFind.sln
dotnet run --project ScreenFind.App
```

التطبيق بلا نافذة رئيسية، فلا تتوقع ظهور شيء بعد التشغيل سوى إشعار قصير وأيقونة عدسة في شريط
النظام. ويندوز 11 يخفي أيقونات التطبيقات الجديدة داخل السهم المطوي، فاسحبها إلى الشريط إن أردت
الوصول السريع إليها. في أول تشغيل تُفتح شاشة الإعدادات تلقائياً.

تشغيل نسخة ثانية بينما الأولى تعمل لا يفتح نافذة جديدة: النسخة الثانية تطلب من العاملة إظهار
صندوق البحث ثم تُغلق نفسها.

### الاختصارات

| المفتاح | الوظيفة |
|---|---|
| `Ctrl+Shift+F` | إظهار صندوق البحث أو إخفاؤه |
| `Enter` أو `F3` | النتيجة التالية |
| `Shift+Enter` | النتيجة السابقة |
| `Ctrl+C` | نسخ النص المستخرَج كاملاً إلى الحافظة |
| `Esc` | إغلاق كل شيء وإعادة التركيز إلى النافذة الأصلية |

قائمة أيقونة شريط النظام فيها: بحث في الشاشة، الإعدادات، إنهاء.

### حزمة تنفيذية واحدة بلا مُثبِّت

```bash
dotnet publish ScreenFind.App -c Release
```

الملف الناتج في `ScreenFind.App\bin\Release\net8.0-windows10.0.19041.0\win-x64\publish`.

## الإعدادات

من أيقونة شريط النظام ← الإعدادات. تُحفظ في `%APPDATA%\ScreenFind\settings.json` وتُطبَّق فور
الحفظ بلا إعادة تشغيل.

| المجموعة | ما يمكن ضبطه |
|---|---|
| اللغة | عربي، إنجليزي، أو حسب لغة ويندوز. يتغير معها اتجاه الواجهة |
| الاختصار العام | أي تركيبة فيها مُعدِّل واحد على الأقل، ويُعاد تسجيلها فور الحفظ |
| الاستخراج | تفعيل طبقة UI Automation، لغات OCR، معامل التكبير، طريقة إعادة التحجيم، التدرّج الرمادي |
| المطابقة | المطابقة الضبابية، أدنى تشابه (0.60–1.00)، أقصى عدد نتائج |
| ألوان التظليل | لون كل النتائج، لون النتيجة النشطة، لون إطارها، بصيغة `#AARRGGBB` |
| السلوك | مهلة البحث أثناء الكتابة، التشغيل مع بدء ويندوز (يكتب في `HKCU\...\Run` فقط) |

تغيير إعدادات الاستخراج يمسح النص المخزَّن من آخر قراءة، فتُقرأ الشاشة من جديد في البحث التالي.

## بنية المشروع

- **`ScreenFind.Core`** — كل المنطق، بلا أي اعتماد على WPF ليبقى قابلاً للاختبار: التقاط الشاشة،
  طبقتا الاستخراج، تطبيع النصوص ومطابقتها، الاختصار العام، الإعدادات، وكل استدعاءات Win32 في
  ملف واحد.
- **`ScreenFind.App`** — واجهة WPF: صندوق البحث، طبقة التظليل، شاشة الإعدادات، أيقونة شريط
  النظام، وإدارة النسخة الواحدة.
- **`ScreenFind.Cli`** — أداة كونسول تطبع الكلمات المستخرَجة وإحداثياتها.
- **`ScreenFind.Feasibility`** — أداة قياس دقة OCR وتوليد عينات اختبار.
- **`ScreenFind.Tests`** — 77 اختباراً: المطبّع، خريطة المواضع، محرك المطابقة، تحويل الإحداثيات،
  واختبارات تكامل تشغّل المسار كاملاً على صور حقيقية.
- **`build`** — ملف المانيفست (PerMonitorV2)، الأيقونة، ملف WiX، وسكربت بناء المُثبِّت.

### مسار المعالجة

عند الضغط على `Ctrl+Shift+F`:

1. تُحفظ النافذة النشطة **قبل** ظهور أي واجهة، لأن إظهار صندوق البحث يسرق التركيز.
2. يُمرَّر الطلب إلى `ExtractionPipeline`.
3. الطبقة الأولى `UiaTextExtractor` تقرأ النص وإحداثياته من التطبيق نفسه، بلا التقاط صورة. تنجح
   في المتصفحات وWord وتطبيقات WinUI، وهي أسرع وأدق.
4. إن لم تُرجع نصاً معقولاً، تُلتقط صورة النافذة، تُعالَج مسبقاً، ثم يعمل محركا OCR العربي
   والإنجليزي بالتوازي وتُدمج نتائجهما.
5. يُطبَّع النص والاستعلام بنفس الدالة، تجري المطابقة الحرفية ثم الضبابية، وتُرسم النتائج على
   طبقة تظليل لكل شاشة.

## أدوات التشخيص

لفحص ما يستخرجه التطبيق من نافذة معيّنة:

```bash
dotnet run --project ScreenFind.Cli -- --once 4 --search "المكتبة"
```

يطبع اسم النافذة، الطبقة التي أعطت النتيجة، الزمن، الكلمات بإحداثياتها الفعلية، ونتائج البحث.
`--ocr-only` و `--uia-only` لعزل طبقة واحدة.

لقياس دقة OCR على جهازك:

```bash
dotnet run --project ScreenFind.Feasibility -- gate
```

يولّد عينات بالعربية والإنجليزية في ثلاث حالات (نص مرسوم على الشاشة، شبيه بمسح ضوئي، متدهور
بشدة)، ويقيس الدقة لكل حالة ولكل طريقة معالجة مسبقة، ثم يكتب تقريراً في `docs/`. شغّله على
جهازك لأن النتيجة تتبع حزم اللغة المثبّتة لديك.

لقياس محتوى حقيقي بدل العينات المولَّدة: ضع لقطات شاشة في `samples/synthetic/` بالتسمية
`ar_*_scan.png` أو `en_*_scan.png`، وبجانب كل صورة ملف `.txt` بنفس الاسم يحوي نصها الصحيح، ثم
شغّل `run` بدل `gate`.

لرؤية المخرجات الخام لمحرك OCR على صورة واحدة:

```bash
dotnet run --project ScreenFind.Feasibility -- dump <image.png> ar x2-bicubic
```

## قرارات تقنية

1. **ترتيب الكلمات في السطر العربي.** محرك ويندوز يعيد كلمات السطر بترتيبها البصري من اليسار
   إلى اليمين، وهو معكوس منطقياً في العربية. بدون تصحيح يفشل البحث عن العبارات ويخرج النص
   المنسوخ مقلوباً رغم أن الكلمات نفسها صحيحة. `ReadingOrder` يعيد ترتيب كل سطر حسب اتجاهه.
2. **الدمج بين المحركين على مستوى السطر لا الكلمة.** دمج الكلمات فردياً يخلط ترتيب القراءة في
   العربية. لكل منطقة من الشاشة يُختار السطر الأعلى وزناً، والوزن هو عدد حروف السكربت المطابق
   مضروباً في نسبة المطابقة. النسبة وحدها لا تكفي: المحرك الإنجليزي على سطر عربي يُخرج حروفاً
   لاتينية عشوائية نسبة مطابقتها للسكربت اللاتيني 100%.
3. **`IOcrEngine` نقطة استبدال واحدة.** محرك ويندوز جيد على النص المرسوم وأضعف على المحتوى
   شديد التدهور. استبداله بـ PaddleOCR أو Tesseract يكلّف إضافة كلاس واحد، ولا تخرج أنواع
   `Windows.Media.Ocr` من `WindowsOcrEngine`.
4. **`Rect` خاص بالنواة** بدل `System.Windows.Rect`، حتى تبقى `ScreenFind.Core` بلا WPF.
5. **صندوق البحث يأخذ التركيز.** الكتابة تحتاج تركيز لوحة المفاتيح، ولهذا تُحفظ النافذة الهدف
   قبل إظهار الصندوق لا بعده.
6. **`ValuePattern` غير مستخدم في طبقة UIA** لأنه لا يعطي إحداثيات لكل كلمة، والتظليل بلا
   إحداثيات لا معنى له. هذه الحالات تسقط إلى OCR.
7. **التدرّج الرمادي قبل التكبير.** النتيجة نفسها بربع العمل. ولا يُحوَّل النص إلى أبيض وأسود
   صرف (binarization) لأنه يُضعف دقة محرك ويندوز. التكبير يُقلَّص تلقائياً إن تجاوزت الصورة 24
   مليون بكسل أو 10000 بكسل في أي بُعد.
8. **نصوص الواجهة في قاموس C# واحد** بدل ملفات resx وsatellite assemblies. أسهل في المراجعة
   وأأمن في حزمة single-file. تُعاد النوافذ بناءً عند تغيير اللغة لأن الاتجاه يُحسم وقت الإنشاء.
9. **مقاس النوافذ بالبكسل الفعلي.** تهيئة WinForms (المستخدَمة لأيقونة شريط النظام) قد تغيّر
   سياق DPI للخيط، فيبني WPF إطاراً بمقاس 96 DPI ويرسم محتواه مكبّراً فيُقصّ. الحل تثبيت الخيط
   على PerMonitorV2 وضبط المقاس والتوسيط عبر `SetWindowPos` بعد أول رسم، مع قصّه على مساحة عمل
   الشاشة.
10. **نسخة واحدة تعمل في كل وقت.** النسخة الثانية كانت تفشل صامتة في تسجيل الاختصار فيبدو
    التطبيق كأنه لا يعمل. صارت تطلب من النسخة العاملة إظهار صندوق البحث ثم تُغلق نفسها.
11. **نصوص المُثبِّت بالإنجليزية.** جدول نصوص MSI مرتبط بصفحة ترميز واحدة، وإبقاؤه على 1252
    يضمن عمله على كل الأنظمة. أما واجهة التطبيق فتدعم اللغتين.

### مطبّات ويندوز التي عولجت

| المطبّ | المعالجة |
|---|---|
| التطبيق يلتقط واجهته نفسه ويقرأها | `SetWindowDisplayAffinity` مع `WDA_EXCLUDEFROMCAPTURE` على كل نوافذه |
| ضياع النافذة المستهدفة عند ظهور الواجهة | حفظ `GetForegroundWindow()` قبل إظهار أي شيء |
| انحراف التظليل على الشاشات المكبّرة | `PerMonitorV2` في المانيفست، وكل تحويلات الإحداثيات في `CoordinateMapper` وحده |
| بطء OCR | كل العمليات غير متزامنة، مع تخزين نتيجة الاستخراج بهاش اللقطة |
| تعدد الشاشات | طبقة تظليل مستقلة لكل شاشة بمعامل DPI الخاص بها |
| استثناءات UIA غير المتوقعة | `try/catch` حول كل استدعاء ومهلة قصوى ثانيتان |
| نقرات الفأرة تصطدم بطبقة التظليل | `WS_EX_TRANSPARENT` فتمرّ النقرات إلى التطبيق تحتها |
